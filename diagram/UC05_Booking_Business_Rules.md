# UC05 - Booking Business Rules

| Activity | BR Code | Description |
|---|---|---|
| (4) | BR1 | Authentication Rules:<br>❖ The system checks [authUser] (View: `app/hotel/[id]/page.tsx`, `app/booking/page.tsx`, `app/booking/payment/page.tsx`, Hook: `useAuth()`, Route guard: `CustomerOnlyRoute`).<br>❖ If [authUser] is null, the system displays the login form.<br>❖ Else the customer can continue booking. |
| (7) | BR2 | Room Selection Rules:<br>❖ The system checks [roomId], [rooms], [quantity], and selected room type (View: `app/hotel/[id]/page.tsx`, Function: `handleBookRoom()`).<br>❖ If [quantity] > 1, all selected rooms must belong to the same [roomTypeId].<br>❖ If the customer selects different room types for a multi-room booking, the system shows MSG31.<br>❖ Else the system redirects to the booking form with [hotelId], [hotelName], [roomId], [roomName], [roomPrice], [checkIn], [checkOut], [adults], [children], and [quantity] (Route: `/booking?...`). |
| (8) | BR3 | Message Rules:<br>❖ The system shows MSG31 (View: `app/hotel/[id]/page.tsx`, Function: `handleBookRoom()`). |
| (13) | BR4 | Validate Rules:<br>❖ The system checks [guestName], [guestEmail], and [guestPhone] (View: `app/booking/page.tsx`, Function: `runValidation()`).<br>❖ Guest name checks:<br> &nbsp;&nbsp;• If [guestName] is null or blank, the system shows MSG32.<br> &nbsp;&nbsp;• If trim([guestName]).length < 2, the system shows MSG33.<br> &nbsp;&nbsp;• If [guestName] contains characters outside a-z, A-Z, or spaces, the system shows MSG34.<br> (Function: `validateName()`).<br>❖ If [guestEmail] is null or blank, the system shows MSG35 (Function: `validateEmail()`).<br>❖ If [guestEmail] does not match email format, the system shows MSG36 (Function: `validateEmail()`).<br>❖ If [guestPhone] is null or blank, the system shows MSG37 (Function: `validatePhone()`).<br>❖ The system removes non-digit characters from [guestPhone]. If it has 10 digits and starts with 0, the leading 0 is removed (Function: `handlePhoneChange()`).<br>❖ If [guestPhone] does not contain exactly 9 digits after normalization, the system shows MSG38 (Function: `validatePhone()`).<br>❖ Else the booking information is valid. |
| (14) | BR5 | Message Rules:<br>❖ The system shows the corresponding validation message from MSG32 to MSG38 (View: `app/booking/page.tsx`, State: `errors`). |
| (15) | BR6 | Create Booking Request Rules:<br>❖ The system creates [payload] from [userId], [hotelId], [hotelName], [checkInDate], [checkOutDate], [adults], [children], [contactName], [contactEmail], [contactPhone], [specialRequests], [pointsToUse], and [items] (View: `app/booking/page.tsx`, Function: `handleProceed()`).<br>❖ [items] contains one item with [roomTypeId], [roomTypeName], [ratePlanId], [checkInDate], [checkOutDate], [quantity], [unitPrice], [nights], [guestName], and [cancellationPolicy] (Frontend API: `bookingApi.createBooking(payload)`, DTO: `CreateBookingPayload`, `BookingItemPayload`). |
| (16) | BR7 | Room Hold Rules:<br>❖ The system checks [items].<br>❖ If [items] is null or empty, booking creation fails (Endpoint: `POST /api/bookings`, Controller: `BookingController.createBooking()`).<br>❖ If [items] has more than one item, all items must have the same [roomTypeId].<br>❖ The system calculates [totalQuantity] from sum([items.quantity]) (Service: `BookingService.createBooking()`).<br>❖ The system creates [holdRequest] from [roomTypeId], [checkInDate], [checkOutDate], and [totalQuantity].<br>❖ The system calls availability service to create [holdId] (External client: `HotelAvailabilityClient.holdRooms()`, Endpoint: `POST /api/v1/availability/hold`, Hotel service: `AvailabilityService.holdRooms()`, DTO: `HoldRequest`, `HoldResponse`). |
| (17) | BR8 | Availability Rules:<br>❖ If the availability service cannot hold enough rooms, the system does not create the booking (External service: `AvailabilityService.holdRooms()`).<br>❖ Else [holdId] is saved for the booking and [holdExpiresAt] is set (Service: `BookingService.createBooking()`, Entity: `RoomHold`, `Booking`, Repository: `RoomHoldRepository`, `BookingRepository`). |
| (18) | BR9 | Message Rules:<br>❖ The system shows MSG39 (View: `app/booking/page.tsx`, Function: `handleProceed()`, State: `submitError`). |
| (19) | BR10 | Amount Calculation Rules:<br>❖ For each booking item, [subtotal] = [unitPrice] * [quantity] * [nights].<br>❖ [totalAmount] is the sum of all item subtotals before discounts (Service: `BookingService.createBooking()`, DTO: `CreateBookingRequest`, `CreateBookingItemRequest`, Entity: `Booking`, `BookingItem`). |
| (20) | BR11 | Loyalty Point Rules:<br>❖ If [pointsToUse] is provided and greater than 0, the system gets available loyalty points by [userId] (View: `app/booking/page.tsx`, Frontend API: `loyaltyApi.getUserPoints(userId)`).<br>❖ If available points < [pointsToUse], the point discount is ignored.<br>❖ [pointsDiscount] = [pointsToUse] * 1000 (Backend client: `LoyaltyPointsClient.getLoyaltyPoints()`).<br>❖ [pointsDiscount] cannot exceed 50% of [totalAmount].<br>❖ If loyalty validation fails, [pointsDiscount] is set to 0 and booking creation continues (Service: `BookingService.createBooking()`). |
| (21) | BR12 | Booking Creation Rules:<br>❖ The system creates [booking] with [status] = PENDING, [paidAmount] = 0, [totalAmount] = [totalAmount] - [voucherDiscount] - [pointsDiscount], [holdId], and [holdExpiresAt] (Service: `BookingService.createBooking()`, Repository: `BookingRepository.save()`, Entity: `Booking`). The service stores `holdExpiresAt` using `holdResponse.expiresAt` returned from the availability service (fallback to `now + 15 minutes` only when `expiresAt` is missing).<br>❖ The system publishes a booking status event with [bookingStatus] = PENDING (Event: `HotelEventPublisher.publishBookingStatus()`). |
| (22) | BR13 | Booking Item Rules:<br>❖ The system creates booking items from [items].<br>❖ Each booking item stores [roomTypeId], [roomTypeName], [ratePlanId], [checkInDate], [checkOutDate], [quantity], [unitPrice], [nights], [subtotal], [taxFee], [cancellationPolicy], and [guestName] (Service: `BookingService.createBooking()`, Repository: `BookingItemRepository.saveAll()`, Entity: `BookingItem`). |
| (27) | BR14 | Payment Validation Rules:<br>❖ The system checks [bookingId], [paymentMethod], [booking.status], and [timeRemaining] (View: `app/booking/payment/page.tsx`, Functions: `handleConfirm()`, `formatTime()`).<br>❖ If [bookingId] is null or blank, the system shows MSG40 (Frontend API: `bookingApi.getBooking(bookingId)`, Endpoint: `GET /api/bookings/{id}`).<br>❖ If [booking.status] is CONFIRMED, CHECKED_IN, or CHECKED_OUT, the system shows MSG49.<br>❖ If [booking.status] is CANCELLED or NO_SHOW, the system shows MSG50.<br>❖ If [booking.status] is not PENDING or PENDING_PAYMENT and does not match the cases above, the system shows MSG51.<br>❖ If [timeRemaining] <= 0, the system shows MSG42.<br>❖ Else the payment confirmation is valid. |
| (28) | BR15 | Message Rules:<br>❖ The system shows MSG40, MSG42, MSG43, MSG49, MSG50, or MSG51 (View: `app/booking/payment/page.tsx`, State: `error`). |
| (30) | BR16 | VNPay Payment Creation Rules:<br>❖ The system checks the latest payment attempt of [bookingId] (View: `app/booking/payment/page.tsx`, Function: `handleConfirm()`, Repository: `PaymentRepository.findFirstByBookingIdOrderByCreatedAtDesc()`).<br>❖ If the latest payment status is not FAILED or CANCELLED, the system does not create another payment.<br>❖ The system checks [booking.status]. If it is not PENDING or PENDING_PAYMENT, payment creation fails.<br>❖ The system verifies [holdExpiresAt]. If [holdExpiresAt] has expired, the system cancels the booking and payment creation fails (Function: `BookingService.ensureActiveHold()`).<br>❖ The system checks [holdId] in hotel-service. If the hold status is HELD and not expired, it continues.<br>❖ The system creates a new payment with [method] = VNPAY, [status] = PENDING, [amount] = [booking.totalAmount], [transactionId], and [vnpayOrderId] (Frontend API: `bookingApi.initVnPay(bookingId)`, Endpoint: `POST /api/payments/vnpay/create?bookingId=...`, Controller: `PaymentController.createVnPayPayment()`, Service: `PaymentService.initVnPayPayment()`, Repository: `PaymentRepository.save()`, VNPay utility: `VnPayUtil.buildQuery()`, `VnPayUtil.hmacSHA512()`).<br>❖ The system updates [booking.status] to PENDING_PAYMENT and returns [redirectUrl]. |
| (34) | BR17 | VNPay Callback Rules:<br>❖ The system receives [orderId], [responseCode], and [transactionId] from VNPay (View: `app/booking/payment/return/page.tsx`, Frontend API: `bookingApi.processVnPayReturn(queryString)`).<br>❖ The system finds [payment] by [vnpayOrderId] = [orderId] (Endpoint: `GET /api/payments/vnpay/return`, Controller: `PaymentController.vnpayReturn()`, Service: `PaymentService.processVNPayCallback()`, Repository: `PaymentRepository.findByVnpayOrderId()`).<br>❖ If [responseCode] = "00", the payment is successful.<br>❖ Else the payment is failed. |
| (35) | BR18 | Payment Failure Rules:<br>❖ The system sets [payment.status] = FAILED (Service: `PaymentService.processVNPayCallback()`).<br>❖ The system stores [vnpayResponseCode] and [vnpayTransactionNo] (Repository: `PaymentRepository.save()`).<br>❖ The system sets [booking.status] = PENDING so the customer can retry before [holdExpiresAt] (Repository: `BookingRepository.save()`).<br>❖ The system does not delete the failed payment (Entity: `Payment`, `Booking`). |
| (35) | BR19 | Hold Retention Rules:<br>❖ When VNPay payment fails, the system does not release [holdId] immediately (Service: `PaymentService.processVNPayCallback()`).<br>❖ The room hold remains active until [holdExpiresAt].<br>❖ If the customer does not retry before [holdExpiresAt], the scheduled task cancels the booking and the active payment attempt (Scheduler: `BookingScheduledTask.processExpiredPaymentHolds()`, Hotel scheduler: `AvailabilityService.releaseExpiredHolds()`). |
| (36) | BR20 | Message Rules:<br>❖ The system shows MSG45, MSG46, MSG47, or MSG48 according to [responseCode] and callback result (View: `app/booking/payment/return/page.tsx`, State: `message`, `status`). |
| (38) | BR21 | Retry Hold Verification Rules:<br>❖ The system checks [bookingId], [booking.status], [holdId], and [holdExpiresAt] (View: `app/booking/payment/return/page.tsx`, `app/booking/payment/page.tsx`, Frontend API: `bookingApi.initVnPay(bookingId)`, Service: `PaymentService.initVnPayPayment()`).<br>❖ If [booking.status] is not PENDING or PENDING_PAYMENT, retry payment is rejected.<br>❖ If [holdExpiresAt] has expired, the system cancels [booking] (Function: `BookingService.ensureActiveHold()`).<br>❖ If [holdId] exists, the system checks the hold status from hotel-service (Function: `BookingService.hasUsableHold()`, External client: `HotelAvailabilityClient.getHold()`).<br>❖ Retry can continue only when the hold status is HELD and the hold is not expired. |
| (39) | BR22 | Hold Validity Rules:<br>❖ If the hold is still valid, the customer can create a new payment attempt (Service: `BookingService.ensureActiveHold()`, Function: `BookingService.hasUsableHold()`).<br>❖ If the hold is expired or not HELD, retry payment is not allowed (External endpoint: `GET /api/v1/availability/hold/{holdId}`). |
| (40) | BR23 | Booking Cancellation Rules:<br>❖ If [holdExpiresAt] has expired during retry, the system sets [booking.status] = CANCELLED (Service: `BookingService.ensureActiveHold()`, Repository: `BookingRepository.save()`).<br>❖ The system publishes a booking status event with [bookingStatus] = CANCELLED (Event: `HotelEventPublisher.publishBookingStatus()`). |
| (41) | BR24 | Message Rules:<br>❖ The system shows MSG41 (View: `app/booking/payment/page.tsx`, State: `error`). |
| (42) | BR25 | Retry Payment Creation Rules:<br>❖ The system keeps previous FAILED payments as history (View: `app/booking/payment/return/page.tsx`, Button route: `/booking/payment?bookingId=...`).<br>❖ The system creates a new VNPay payment attempt only if the latest payment is FAILED or CANCELLED and the booking hold is still valid (Service: `PaymentService.initVnPayPayment()`, Repository: `PaymentRepository.findFirstByBookingIdOrderByCreatedAtDesc()`, `PaymentRepository.save()`).<br>❖ The new payment has a new [id], [transactionId], and [vnpayOrderId]. |
| (46) | BR26 | Retry Callback Rules:<br>❖ The system applies the same VNPay callback rules as BR17 (View: `app/booking/payment/return/page.tsx`).<br>❖ If retry payment fails, BR18 and BR19 are applied (Endpoint: `GET /api/payments/vnpay/return`, Service: `PaymentService.processVNPayCallback()`).<br>❖ If retry payment succeeds, BR29 is applied. |
| (47) | BR27 | Retry Failure Rules:<br>❖ The system sets the retry [payment.status] = FAILED (Service: `PaymentService.processVNPayCallback()`).<br>❖ The system keeps [booking.status] = PENDING (Repository: `PaymentRepository.save()`, `BookingRepository.save()`).<br>❖ The system keeps [holdId] until [holdExpiresAt]. |
| (49) | BR28 | Message Rules:<br>❖ The system shows MSG45, MSG46, MSG47, or MSG48 according to [responseCode] and callback result (View: `app/booking/payment/return/page.tsx`). |
| (50) | BR29 | VNPay Success Payment Rules:<br>❖ The system sets [payment.status] = COMPLETED (Service: `PaymentService.processVNPayCallback()`).<br>❖ The system sets [paidAt] = current time (Repository: `PaymentRepository.save()`).<br>❖ The system stores [vnpayResponseCode] and [vnpayTransactionNo] (Entity: `Payment`). |
| (51) | BR30 | Confirm Hold Rules:<br>❖ The system calls hotel-service to confirm [holdId] (Service: `BookingService.confirmBookingHold()`, External client: `HotelAvailabilityClient.confirmHold()`, External endpoint: `POST /api/v1/availability/hold/{holdId}/confirm`, Hotel service: `AvailabilityService.confirmHold()`).<br>❖ If confirming hold fails, the error is logged. |
| (52) | BR31 | Booking Confirmation Rules:<br>❖ The system sets [booking.status] = CONFIRMED (Service: `PaymentService.processVNPayCallback()`).<br>❖ The system sets [paidAmount] = [payment.amount] (Repository: `BookingRepository.save()`, Entity: `Booking`). |
| (53) | BR32 | Event Rules:<br>❖ The system publishes payment completed event (Service: `PaymentService.processVNPayCallback()`, Event publisher: `HotelEventPublisher.publishPaymentCompleted()`).<br>❖ The system publishes booking status event with [bookingStatus] = CONFIRMED (Event publisher: `HotelEventPublisher.publishBookingStatus()`).<br>❖ If [usedPoints] > 0, the system deducts loyalty points (External client: `LoyaltyPointsClient.usePoints()`).<br>❖ The system earns loyalty points for the confirmed booking (External client: `LoyaltyPointsClient.earnPoints()`). |
| (54) | BR33 | Message Rules:<br>❖ The system shows MSG44 (View: `app/booking/payment/return/page.tsx`). |
| (55) | BR34 | No Retry Rules:<br>❖ If the customer does not retry payment, [booking.status] remains PENDING until [holdExpiresAt] (View: `app/booking/payment/return/page.tsx`).<br>❖ The scheduled task will cancel the booking after [holdExpiresAt] if payment is not completed (Scheduler: `BookingScheduledTask.processExpiredPaymentHolds()`, Hotel scheduler: `AvailabilityService.releaseExpiredHolds()`). |
| (56) | BR35 | Message Rules:<br>❖ The system shows MSG47 or MSG48 (View: `app/booking/payment/return/page.tsx`). |
| (57) | BR36 | Direct VNPay Success Rules:<br>❖ If the first VNPay payment succeeds, the system applies BR29 (Endpoint: `GET /api/payments/vnpay/return`, Service: `PaymentService.processVNPayCallback()`). |
| (58) | BR37 | Direct Confirm Hold Rules:<br>❖ The system applies BR30 (Service: `BookingService.confirmBookingHold()`, External client: `HotelAvailabilityClient.confirmHold()`). |
| (59) | BR38 | Direct Booking Confirmation Rules:<br>❖ The system applies BR31 (Service: `PaymentService.processVNPayCallback()`, Repository: `BookingRepository.save()`). |
| (60) | BR39 | Direct Event Rules:<br>❖ The system applies BR32 (Event publisher: `HotelEventPublisher.publishPaymentCompleted()`, `HotelEventPublisher.publishBookingStatus()`, External client: `LoyaltyPointsClient`). |
| (61) | BR40 | Message Rules:<br>❖ The system shows MSG44 (View: `app/booking/payment/return/page.tsx`). |
| (62) | BR41 | Hotel Payment Creation Rules:<br>❖ The system checks the latest payment attempt of [bookingId] (View: `app/booking/payment/page.tsx`, Frontend API: `bookingApi.createPayment(bookingId, amount, "HOTEL")`).<br>❖ If the latest payment status is not FAILED or CANCELLED, the system does not create another payment.<br>❖ The system checks [booking.status]. If it is not PENDING or PENDING_PAYMENT, payment creation fails (Endpoint: `POST /api/payments`, Controller: `PaymentController.createPayment()`, Service: `PaymentService.createPayment()`).<br>❖ The system verifies [holdExpiresAt]. If [holdExpiresAt] has expired, the system cancels the booking and payment creation fails (Function: `BookingService.ensureActiveHold()`).<br>❖ The system creates a payment with [method] = HOTEL, [status] = ONSITE_PENDING, [amount], and [transactionId] (Repository: `PaymentRepository.save()`). |
| (63) | BR42 | Hotel Payment Status Rules:<br>❖ The system updates [booking.status] to PENDING_PAYMENT (Service: `PaymentService.createPayment()`, Repository: `BookingRepository.save()`).<br>❖ [paidAmount] remains 0 until hotel staff confirms payment (Entity: `Booking`, `Payment`). |
| (64) | BR43 | Message Rules:<br>❖ The system shows MSG55 (View: `app/booking/payment/hotel-confirm/page.tsx`). |
| (65) | BR44 | View Confirmation Rules:<br>❖ The customer can view booking information by [bookingId] (View: `app/booking/[id]/page.tsx`, `app/booking/history/page.tsx`).<br>❖ The system displays [booking.status], [hotelName], [checkInDate], [checkOutDate], [items], [totalAmount], [paidAmount], and contact information (Frontend API: `bookingApi.getBooking(id)`, `bookingApi.getUserBookings(userId)`, Endpoint: `GET /api/bookings/{id}`, `GET /api/bookings/user/{userId}`, Controller: `BookingController.getBooking()`, `BookingController.getUserBookings()`, Service: `BookingService.getBooking()`, `BookingService.getUserBookings()`). |
