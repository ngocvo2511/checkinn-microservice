## 2. Root causes and minimal design

1. `SearchCriteriaState.update` deliberately replaces location/date/occupancy groups, removing omitted members. The old clarification asked for the entire group without identifying missing members or explaining reconfirmation. The validator is retained; the question now targets missing members and explains the necessary related-group confirmation.
2. Vietnamese grammar used literal digits/one-two-three substitutions and a fixed city map. Exact number/date/money interpretation is expanded by a bounded lexical helper, while destination label recognition is separated from catalog identity resolution.
3. Mixed ambiguous text was atomically rejected but its question could imply normal extraction or ask unrelated destination details. It now states that no changes from that sentence were applied; increments are explicitly distinguished from replacement.
4. The historical40-case suite had never been replayed. It contains older response/status/target/browse expectations that are not all implemented by the current internal Java NLU. The new audit exposes these mismatches instead of replacing the manifest or marking similar policy tests PASS.

Pipeline remains input gate → one TurnBudget → existing exclusive lease/revision admission → deterministic extraction → closed typed proposal → existing authoritative criteria validation/merge → clarification or original orchestrator → PolicyExecutor →10 READ tools → GroundingGate. No second store, pending-state map, automatic model extractor or extra budget exists.

## 4. Grammar coverage and boundaries

`VietnameseNumbers` accepts bounded literal integers (at most9999, bounded word/token length), digit words0–9, tens/hundreds/thousands, common mốt/lăm/tư forms, and exact compound money. Examples verified: một/hai/ba/bốn người lớn, hai phòng, bốn mươi, một triệu rưỡi, một triệu năm trăm nghìn =1500000 VND. Integer operations are bounded/checked; money uses BigDecimal, never floating-point rounding. Domain guest/room/price validation still applies after normalization. Unsupported constructions remain visible to remainder validation instead of being guessed.

Dates verified: “ngày mười lăm tháng mười hai năm hai nghìn không trăm hai mươi sáu”, “15 tháng12 năm2026”, optional “ngày”, “nhận phòng ngày15/12/2026”, “trả phòng ngày17/12/2026” and explicit check-in corrections. Shared-year intervals1–3/12/2026 and1/12 đến31/12/2026 use the year explicitly written for that interval; they do not infer the current year. Both endpoints are strict civil dates and the existing max30-night/business-zone validation remains authoritative. Missing year, malformed/contradictory date expressions, ambiguous weekend/month and unsupported number syntax ask or reject. `ngày mai` still uses injected Clock and Asia/Ho_Chi_Minh; production contains no hardcoded today or model time.

`DestinationLabels` is a trusted immutable label-only snapshot abstraction, max200 labels, max120 characters, normalized alias collision rejection. Defaults retain the original8 labels; no large new geography list or live catalog import was invented. `VietnameseParser(DestinationLabels)` is an internal seam tested with synthetic labels; normal AgentOrchestrator still uses the defaults. Explicit `ở "Cần Thơ"` is accepted as a bounded literal query string without claiming verified geography/identity. No UUID/code is produced. Unquoted arbitrary/fuzzy destination recognition remains conservative. Hotel-name queries no longer cause a city mentioned only inside a quoted hotel name to be treated as a separate location.
